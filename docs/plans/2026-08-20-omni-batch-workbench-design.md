# Omni 批量接单工作台设计

## 目标

把原先一次只能持有一个订单的 Omni 插件流程扩展为独立网页工作台。操作者可一次领取 1–10 个订单，在 Google Flow 并行制作，再将每个公开单视频分享链接准确绑定到对应订单。豆包插件与原有飞书任务池保持不变。

## 用户流程

1. 输入接单人，选择数量，默认 5 单、上限 10 单。
2. 服务端在同一个接单互斥锁内逐条领取任务，并返回已成功领取的订单；中途没有任务或飞书短暂失败时保留并返回已领取部分。
3. 网页为每个订单显示图片、提示词、任务 ID 和独立的 Flow 分享链接输入框。
4. 操作者可以逐条提交，也可以填完多个链接后批量提交。客户端阻止同一链接在当前工作台重复使用，服务端同时保留跨请求的视频 UUID 预约，避免并发错绑。
5. 每条订单独立进入 Flow 下载、R2 上传和公网可读性验证。只有验证成功的订单才回填 `视频地址` 并标记 `已完成`。
6. 单条失败只把该卡片标记为可重试，订单保持 `接单中`；其他卡片继续处理。
7. 批量释放只处理未在转存中的订单。服务端再次校验锁，防止释放其他人的任务。

## 恢复与兼容

- 网页把最多 10 个订单的 `recordId`、`lockId` 和 UI 状态保存在浏览器本地。
- 页面刷新后把本地锁交给服务端逐条校验，恢复仍在接单中的任务；已经完成的任务返回 R2 链接，锁已失效的任务从活动列表移除。
- 原 `/api/claim`、`/api/complete`、`/api/release` 保持兼容。
- 新增批量申领、恢复和批量释放端点，Omni 单条完成端点继续作为唯一回填入口。

## 数据安全

- `去水印原始链接` 是飞书 URL 样式字段，按 `{ text, link }` 写入；`视频地址` 是普通文本字段，继续写字符串。
- 所有完成、恢复和释放操作都校验记录 ID、锁 ID、接单人、制作平台和任务状态。
- Flow 链接仍只接受 `labs.google/fx/tools/flow/shared/video/<UUID>`。
- 页面不保存飞书、R2 或服务器密钥。

## 验证

- 后端回归测试覆盖 URL 字段格式、批量领取、刷新恢复、批量释放、Flow 重复绑定和 R2 成功/失败状态。
- 网页执行语法检查、DOM 冒烟测试、窄屏和桌面截图检查。
- 上线前备份服务器文件；部署后检查健康能力、CORS、页面资源和不带真实订单的参数校验。

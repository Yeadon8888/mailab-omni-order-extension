# Omni 批量自动插件设计

## 目标

把原来的单任务手动插件升级为最多十单的自动生产队列：批量接单后，操作者可逐单或一键启动全部任务；插件自动向 Google Flow 的 Omni Flash 投喂参考图和提示词，监控生成结果，取得公开分享链接，转存 R2 并回填飞书。

## 核心流程

1. 使用现有 `/api/omni/claim-batch` 批量领取并锁定任务。
2. 每次投喂前清空 Flow 提示区，设置 `Video / Ingredients / x1`，避免一单产生多个结果。
3. 通过 Flow 页面隐藏的图片文件控件上传任务图片，在素材选择器中按唯一文件名选中并加入 Prompt。
4. 对 Slate 编辑器派发 `beforeinput`，让 Flow 内部状态真正接收提示词。
5. 图片和提示词投喂按顺序执行；点击 Create 后立即绑定本次新增的生成卡片，因此已经提交的视频可并行生成。
6. 卡片生成成功并出现 `/edit/<UUID>` 后，后台打开非活动结果页。
7. 自动关闭 `Include inputs`，点击 `Copy link`，页面钩子只捕获合法的 Flow 单视频分享链接。
8. 调用现有 `/api/omni/complete`，等待 R2 可读后才完成飞书订单。

## 恢复与降级

- 活动订单、生成状态、分享链接和 R2 Job ID 保存在 `chrome.storage.local`。
- R2 转存中的任务刷新后会继续轮询。
- 页面刷新会丢失 DOM 卡片映射，因此排队、投喂、生成和取链接阶段会明确转为“需重试”，禁止猜测订单对应关系。
- 任一步失败仍可粘贴 Flow 分享链接手动回填。
- 相同 Flow 视频继续由服务端防重复绑定。

## 验收

- 隔离浏览器完整闭环：批量接单 → 图片上传 → Slate 提示词 → 生成卡片映射 → 分享链接 → R2 → 飞书。
- 分享钩子不得捕获普通剪贴板文本。
- 服务端原有八项锁、R2 验证、失败保留和重复视频测试必须全部通过。
